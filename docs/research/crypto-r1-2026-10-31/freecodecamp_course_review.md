## Verified source defects and limitations

All links below point to the inspected commit. The reproduction script executes only extracted upstream method bodies with inert in-memory dependencies. It does not test the complete Django application or broker behavior.

1. **Automated rebalance cannot submit a nonempty order list as written.** [`execute_trading_signals`](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/strategy_engine.py#L161-L192) omits `user_secret`, while the [buy executor](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/snaptrade_client.py#L98-L103) and [sell executor](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/snaptrade_client.py#L156-L161) require it. Isolated nonempty buy and sell cases both raise the missing-secret error before any broker request. The [manual signal view](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/views.py#L526-L555) does supply that secret. This finding concerns the automated route, not proof that every course workflow is broken.

2. **Fractional sell quantities are truncated.** The [sell request](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/snaptrade_client.py#L176-L200) stores the full position quantity but sends `int(position.quantity)`. Inert fixtures produce 1 requested unit from a 1.75-unit position, and 0 from 0.75. They demonstrate the constructed request, not the broker's response. Copying this logic would leave a matched-quantity contract unsatisfied.

3. **Submission is not reconciled execution.** The [manual view](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/views.py#L510-L588) marks a signal executed after submission and has no already-executed guard before another POST. The [automated strategy](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/strategy_engine.py#L167-L198), if its credential defect were fixed, would allocate buys from target sale values before proving corresponding fills. Future reuse requires idempotent intent IDs, partial-fill quantities, reconciled balances and explicit unresolved exposure. Those are acceptance requirements, not claims that R1 implemented execution.

4. **The backtest is unfinished.** [`run_backtest`](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/strategy_engine.py#L291-L324) returns `Backtest implementation pending`; the isolated check reproduced it. Its zero result fields are placeholder values, not measured performance. No Sharpe ratio, win rate or return estimate should be inferred from this project.

5. **Data date selection is not our information-availability contract.** The [database lookup](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/momentum_calculator.py#L59-L73) takes the earliest price in a symmetric seven-day window; the [API lookup](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/massive_client.py#L445-L474) takes the nearest date. Cache and fallback can therefore choose different prices. A date after the target does not necessarily mean after the decision because the intended endpoints are months earlier, so this is not blanket proof of look-ahead bias. It does mean we cannot reuse this resolver to certify historical availability or exact Donchian lookbacks.

6. **The selection description is looser than the code.** The [README feature list](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/README.md#L7-L12) says to sell positions that drop out of the top quintile; [actual signals](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/strategy_engine.py#L101-L155) sell held bottom-quintile names and allocate cash only among new top-quintile candidates. This does not continuously equal-weight the full portfolio. The [stock universe](https://github.com/nickmccullum/algorithmic-trading/blob/d549ec2a15f0f6a5738ebfc54213afc944b2af36/project1/trading/services/massive_client.py#L413-L422) is an explicit demonstration list, not point-in-time historical index membership.

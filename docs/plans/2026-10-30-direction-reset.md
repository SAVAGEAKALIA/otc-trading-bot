# Direction reset (2026-10-30)

## 1. The finding that decides everything

IQ Option OTC binaries pay about 85% on a win. Breakeven is `1 / 1.85 = 54.05%`.

| Evidence | Sample | Result | Breakeven |
|---|---:|---:|---:|
| Live trades on the server (`data/trade_log.json`, Jul 27-28) | 250 settled | 53.2%, 95% CI [47.0%, 59.3%], ROI -2.1% | 54.2% |
| Project's own CatBoost, untouched test split | 22,674 | log-loss 0.69316 (ln 2 = 0.69315), Brier 0.2500 | n/a |
| Candle rules (lag-1, 3-streak, MHI) on 2m OTC candles, 15 pairs | 1,259,483 | best 50.07% | 54.05% |
| Walk-forward logistic on 6 lagged returns, 2m/5m/15m | 1.27M / 765k / 269k | 50.05% / 50.05% / 50.22% | 54.05% |
| Crowd-contrarian (trader mood, top/bottom quintile) | 22,809 per side | 50.7% / 50.8% | 54.05% |

Reproduce:

```bash
python -m trading_platform.apps.edge_audit --candles data/ml/mtf_candles.parquet
python -m trading_platform.apps.edge_audit --trade-log data/trade_log.json
```

The OTC feed is generated by the broker. The broker is also the counterparty
and sets the payout. The 1.27M-candle tests show no exploitable structure, and
the best signal found (crowd-contrarian) is 3 points short of breakeven. No
amount of ML, strategy voting, martingale, or engineering fixes this. Martingale
only reshapes the loss distribution.

External research agrees:

- No open-source IQ Option, Pocket Option, or Quotex bot publishes verified
  out-of-sample profit. The popular ones run martingale plus affiliate links.
- The most-starred IQ Option API (Lu-Yi-Hsun/iqoptionapi, 391 stars) has had
  no code commit since 2021. Its issue #369 (2026-02) reports it no longer works.
- ESMA banned retail binaries in the EU (2018). ASIC found about 80% of retail
  clients lost money and extended its ban to 2031.

the side the crowd bets on. It replicates on both datasets, and it grew from

still about 3 points short of breakeven overall, and 2.7 points short in the
stronger second half.

No single pair or UTC hour clears breakeven after a Bonferroni correction
across 39 slices. The best slice is EUR/USD at 52.8%. Split by time, EUR/USD
goes from 50.4% in the first half to 54.9% in the second. That number was found
by searching slices, so it is a lead, not a result. The only valid test is a
pre-registered forward test on data collected after Oct 8.

### 1c. Kaggle model search: frozen rubric

The rubric was written and hashed before any training:
`/tmp/otc-kaggle-edge/critique/rubric.md`, sha256 `a5a65f56…`.

- **Splits** are by the label candle's open (UTC):
  - train: before Sep 8
  - validation: Sep 8 01:00 to Sep 22
  - holdout: Sep 22 01:00 to Oct 8
  - A 1-hour purge sits before validation and before holdout.
- **Thresholds** are picked on validation only: the confidence quantile in
  {0, .5, .8, .9, .95, .98} with the best validation win rate and at least 300
  validation trades.
- **PASS** requires all of the following on the holdout:
  - The Wilson lower bound is above 54.05%, at a Bonferroni z for K = 14 configs.
  - At least 300 trades.
  - Both holdout halves are above 54.05%.
  - Local onnxruntime reproduces the holdout trades and wins exactly.

Code lives in `trading_platform/research/studies/`:
- `otc_feature_matrix.py` builds the causal matrix: 30 body lags, wicks,
  returns, RSI, range position, streak, cross-asset market factor, time, and
  crowd mood with deltas. Its tests rewrite the future and assert the past is
  unchanged. Five leak mutants are each caught.
- `kaggle_edge_search/train_edge_search.py` is the GPU kernel with 7 strategies
  for each of the 2m and 5m expiries.
- `kaggle_edge_search/push.sh` uploads a private dataset and runs the kernel.
- `kaggle_edge_search/verify_onnx.py` re-scores the ONNX models locally.

### 1d. Kaggle result (run 1, 2026-10-30, T4 x2, 3.2 min)

The run used 2,918,345 rows and 73 features, and evaluated K = 14 configs
(Bonferroni z = 2.914). **No config passes.** Validation log-loss for every
model is 0.6930-0.6932 (ln 2 = 0.69315), so the models found nothing to learn
before any threshold was applied.

| Strategy | Expiry | Holdout trades | Holdout win rate | Bonferroni CI | ROI |
|---|---|---:|---:|---|---:|
| meta_contrarian | 2m | 767 | 53.98% | [48.7%, 59.1%] | -0.1% |
| catboost_all | 2m | 2,500 | 52.52% | [49.6%, 55.4%] | -2.8% |
| ensemble | 2m | 12,757 | 51.75% | [50.5%, 53.0%] | -4.3% |
| mlp | 2m | 2,690 | 51.67% | [48.9%, 54.5%] | -4.4% |
| catboost_mood | 2m | 3,112 | 51.51% | [48.9%, 54.1%] | -4.7% |
| meta_contrarian | 5m | 3,209 | 51.60% | [49.0%, 54.2%] | -4.5% |
| gru | 2m | 28,691 | 50.89% | [50.0%, 51.8%] | -5.9% |
| the other 7 configs | 2m/5m | | 49.2% to 50.2% | | -7% to -9% |

- **meta_contrarian at 2m is the only result near breakeven.** Its holdout
  halves were 55.96% and 51.97%, so it fails criterion 3. Its CI is 10 points
  wide, so it fails criterion 1. It is a model on top of the crowd-contrarian
  effect from 1b, and the plain contrarian rule scored 52.1% on the same rows.
- **ONNX:** native-to-ONNX parity is within 6.0e-8 for every model. A local
  onnxruntime re-run reproduced 13 of 14 configs exactly. The 14th
  (catboost_all, 5m) differs by 3 trades out of 6,083. Those 3 come from 57
  rows within 1e-6 of the threshold, where float32 rounding flips the
  selection. Evidence: `/tmp/otc-kaggle-edge/critique/verify_run1.txt`.
- **The holdout is now spent.** Any further model search needs data collected
  after Oct 8 as its holdout. Re-using this holdout would turn it into a
  validation set.
- **Disclosure:** the frozen rubric said ONNX must reproduce the holdout
  "exactly". The tolerance for boundary ties (rows within 1e-6 of the cut) was
  added to `verify_onnx.py` after run 1. It excuses at most the number of rows
  inside that band, and only one config used it.

### 1e. Adversarial review and what it changes

A separate critic reviewed the code, the matrix, and the run outputs without
seeing my reasoning. Verdict: **RESULT HOLDS.**

- Labels match raw candles in 100% of 858,211 checked rows.
- No leakage was found.
- The kernel detects injected edges: a 58% global edge in 9 of 14 configs, a
  70% edge on a 5.8% subset in 7 of 14, and the unmodified sample in 0 of 14.

Two caveats change how to read "NO EDGE":

1. **Power.** Thresholds mostly kept 2,500-3,900 holdout trades. At z = 2.91,
   passing then needs a true win rate of about 57%. A real 55% edge would
   probably have been missed. The defensible claim is "no edge of about 57% or
   more at the selected volumes, and no model learned anything (ln 2)".
2. **Bad mood readings.** 28.7% of raw mood samples are exactly 0 or 1. They
   look like no-volume snapshots, and they made up 64% of the
   `meta_contrarian` training subset. Restricted to 0.30 <= |mood - 0.5| < 0.45,
   plain contrarian at 2m scored:

   | Split | Win rate | Trades |
   |---|---:|---:|
   | Train | 50.8% | |
   | Validation | 53.2% | |
   | Holdout | 54.9% | 9,794 |

   The holdout Bonferroni lower bound is 53.4%, so it fails. The band was also
   chosen after seeing the holdout. It is the strongest and only rising effect
   in the data.

Fixed after review:
- `clean_mood` drops degenerate readings. The first version only dropped
  exact 0/1 values, and none exist. The degenerate readings actually sit at
  <= 0.001 or >= 0.999, so the threshold is now 1e-3.
- No-mood rows can no longer count as trades.
- `meta_contrarian` now reports log-loss.
- Minute-of-hour features are added.

The band rule is **pre-registered** in
`docs/research/preregistered_contrarian_band.md` (sha256 `441701f5…`). It may
only be tested on candles after Oct 8. Its "exactly 0 or 1" wording is affected
by the same mistake, but the band 0.30 <= |mood - 0.5| < 0.45 already excludes
every degenerate reading, so the rule itself is unchanged. If the true rate is
54.9%, confirming it takes about 33k trades, roughly 55 days of harvesting at
the observed band rate. Even then it is worth about +1.6% ROI per trade before
slippage or payout changes.

### 1f. Round 2: model-family tournament (Kaggle T4 x2, 16 min)

The rubric was frozen first: `docs/research/kaggle_tournament_round2_rubric.md`,
sha256 `9d22827d…`.

- The data is the 2m matrix rebuilt with clean mood and minute features:
  1.74M rows, 75 features.
- Holdout rows were removed before upload, and the kernel refuses to run if any
  are present.
- The test is walk-forward over five weekly folds from Aug 18 to Sep 21. Each
  fold trains on everything earlier.
- Thresholds for each week come only from earlier weeks' out-of-sample
  predictions. There were about 307k out-of-sample predictions per family.

- **No family is a candidate.** The best pooled win rate is 52.0% (logistic),
  and its Bonferroni CI tops out at 53.5%. No family has 3 weeks above 54.05%.
- **Only the two gradient-boosting libraries learned anything.** XGBoost and
  LightGBM have log-loss CIs entirely below ln 2. The gain is 0.00004 nats,
  roughly 0.3 percentage points of accuracy. It is real and about 13 times too
  small to trade.
- **Retraining on a rolling 14-day window did worse**, so the drift seen in the
  crowd effect is not a learnable regime for these features.
- **Verification:** `verify_tournament.py` recomputed every family's pooled
  result exactly from `oos_predictions.parquet`. It re-ran all 7 tabular ONNX
  models on the 74,916 week-5 rows, with max diff 1.2e-7. The transformer's
  two-input parity was checked inside the kernel at 1.2e-7. kNN has no ONNX
  export by design, because it stores its training rows. Evidence:
  `/tmp/otc-kaggle-edge/critique/verify_run2.txt`.

**Conclusion across both rounds:** 23 model configurations covered 9 families
(linear, 3 gradient-boosting libraries, MLP, GRU, TCN, transformer, kNN), plus
rule and meta-label strategies. Nothing beats breakeven out of sample. The only
consistent structure is crowd-contrarian. At its best it is the 0.30-0.45 mood
band, which is snooped, rising, and pre-registered for a forward test.

### 1g. Round 3: follow vs fade the crowd (walk-forward, real payouts)

The rubric was frozen first: `docs/research/round3_crowd_rubric.md`, sha256
`c131bc32…`.

- The universe is 228,203 2m candles from Jul 31 to Oct 8 with a clean mood
  reading taken at least 1s before the open and no more than 60s old.
- Each trade uses the live turbo-option payout, 0.82-0.89 across 528k samples.
- Crowd features: mood level and its 1/2/5/10-minute deltas, the 10-minute
  max/min/std, a 24h z-score, the market-wide crowd, crowd versus market, and
  whether the crowd agrees with the last candle.
- Code: `trading_platform/research/studies/otc_crowd_study.py`. Its 5 tests
  cover causality, the fade label, a planted 60% fade edge being found, noise
  being rejected, and no trading of a cell before it has a prior record.

**Following the crowd loses in every band, in both periods (44.5-49.9%).**
Fading beats following everywhere. On unseen weeks, though, it peaks at 51.8%
(band 0.30-0.35) against a 54.2% payout-adjusted breakeven.

| Strategy (walk-forward) | Unseen trades | Win rate | Breakeven | ROI | Profitable weeks | Fade share |
|---|---:|---:|---:|---:|---:|---:|
| follow/fade grid (80 rules) | 0 | n/a | n/a | n/a | n/a | n/a |
| lightgbm meta-model | 74,088 | 51.51% | 54.25% | -5.0% | 0/5 | 100% |
| xgboost meta-model | 60,892 | 50.80% | 54.15% | -6.2% | 0/4 | 88% |
| logistic meta-model | 7,768 | 51.87% | 54.16% | -4.2% | 0/5 | 70% |

The grid made no trades: no rule ever cleared breakeven on its prior record.
The models learned to fade, but not by enough. **No candidate.**

The fade effect is non-stationary. In the 0.30-0.45 band it rose week by week:

| Weeks | Fade win rate | ROI |
|---|---:|---:|
| Jul 27 - Aug 2 | 49.2% | |
| Aug 3 - Aug 23 | 50.1% to 50.8% | |
| Aug 31 - Sep 20 | 52.4% to 53.5% | |
| Sep 21-27 | 55.7% | +2.0% |
| Sep 28 - Oct 4 | 55.0% | +0.6% |
| Oct 5-8 (1,477 trades) | 52.2% | -5.0% |

Average payout fell from 0.847 to 0.821 over the same weeks, which moved
breakeven from 54.0% to 54.9%. Payout does not track the crowd trade by trade
(corr(payout, fade win) = 0.0001), but the falling payout level absorbed most
of the growing effect.

**Conclusion of three rounds:**
- The IQ Option crowd is wrong slightly more often than right, and that is the
  only consistent structure in the data.
- It is too weak and too unstable to trade.
- In the only two weeks it beat breakeven, ROI was +2.0% and +0.6%. The next
  week it was -5%.
- Only post-Oct-8 data can tell whether the late-September strength was a
  lasting shift or a peak. The pre-registered band rule (1e) is the test for it.

## 3. Options

### A. Keep tuning the IQ Option bot. Rejected.
Every measurement above says the expected value is negative. More strategies
or more ML repeats the ln 2 result.

### B. Deterministic structural edge on crypto. Recommended core.
Use edges that come from market structure, not from predicting the next candle:

- **Funding-rate carry:** long spot plus short perp on Bybit to collect funding.
  Typical 5-15% APR in normal regimes. The risks are short-leg liquidation on
  spikes, funding flipping negative, and exchange counterparty risk.
- **Dated-futures basis:** lock in the annualized basis, about 5-12%.

Do not build this on the custom `brokers/bybit/` stack. Use mature tooling:

- **freqtrade** (56k stars, pushed daily, monthly releases, 27 open issues)
  covers directional or single-leg work. It already ships dry-run, Telegram
  control, protections, `lookahead-analysis`, and `recursive-analysis`.
- **hummingbot** (20.8k stars) covers the multi-leg funding book. It ships
  `scripts/v2_funding_rate_arb.py` and has paper mode.
- **ccxt** (44.6k stars, weekly releases) is the raw-access fallback.
- Rejected: backtrader (no commit since 2023), FinRL (results do not transfer
  to live), nautilus_trader for now (best engine, but too heavy for one person).

### C. Human-agent research harness. Recommended layer on top of B.
The evidence on LLM trading:

- In Alpha Arena S1, 4 of 6 frontier models lost money. GPT-5 lost about 62%.
- Profit Mirage found TradingAgents' Sharpe fell 55.7% once tested after the
  model's knowledge cutoff.
- In Look-Ahead-Bench, ai-hedge-fund went from +20.7% alpha in-sample to -1.0%
  out of sample.

So the LLM never touches the order path. The pattern that holds up is
microsoft/RD-Agent's: the LLM proposes and deterministic tests judge.

- A `services/llm/` wrapper runs `claude -p --output-format json --json-schema ...`.
  It uses read-only tools, a per-call `--max-budget-usd`, a subprocess timeout,
  and has no exchange keys in its environment.
- Nightly job: the agent proposes 3 hypotheses as JSON. `edge_audit` and a
  walk-forward backtest judge each one, net of fees. Only hypotheses whose CI
  lower bound clears breakeven or fees reach paper trading.
- Live path: a strategy emits a `TradeProposal`. The Telegram bot shows
  Approve/Reject buttons with a 5-minute TTL, restricted to an allowlist of
  users. Risk limits and a kill switch persisted in a file or the DB run in code
  the agent cannot edit.
- The agent also writes the post-trade journal, triages reconciliation
  anomalies, and reviews strategy diffs.

### D. Prediction-market sandbox. Optional, paper first.
Kalshi is CFTC-regulated, so check whether it is available where you are. The
LLM estimates an event probability from cited sources. Deterministic code
trades only when `|p_llm - p_market| > fees + margin`, with capped fractional
Kelly sizing. Prophet Arena shows LLMs are calibrated but lag the market, so
score with Brier against the market price for at least 100 events before
risking money.

### E. Fully autonomous LLM trader. Rejected.
The evidence in C says this loses money, and LLM rank on benchmarks does not
predict trading returns (Spearman about 0.05).

# Receipt recorder failure prevention

1. Repro: a schema/INSERT placeholder count mismatch made every quote write fail during the first gate run.
2. Evidence: the SQLite exception was `table observations has 9 columns but 10 values were supplied`.
3. Classification: deterministic database boundary error.
4. Root cause: implicit `INSERT ... VALUES` did not name its intended columns.
5. Permanent constraint: observation inserts name all nine target columns and bind nine values.
6. Regression: `test_repeated_values_are_distinct_real_receipts_no_cache_repetition` writes through the real callback and real SQLite transaction.
7. Generalization: offline replay writes 234 quote/mood/payout observations and requires exact per-kind counts.
8. Failure containment: SQLite errors roll back the entire receipt transaction, halt ingress, and write a safe storage-failure marker; there is no success-on-partial-write path.
9. Reusable flow: run the free gate plus replay oracle after every schema change; preserve immutable receipt tables and backup lineage.
10. Verification: gate and replay evidence are generated by commands in README. Builder test results do not replace the independent cold critic.

## Broker epoch precision regression

1. Repro: the first live pilot quarantined broker integer-nanosecond stamps whose conversion left a fractional millisecond.
2. Evidence: market-only stamp `1794045176612157505` was rejected while `1794045177000000000` was accepted.
3. Classification: deterministic precision loss at the source metadata boundary.
4. Root cause: `epoch()` required the normalized millisecond value to be integral, although nanosecond broker stamps legitimately carry finer precision.
5. Permanent constraint: exact Decimal unit mapping preserves the original numeric token, reported unit/quantum, exact nanoseconds, and fractional milliseconds; only derived `source_event_ms` uses floor.
6. Regression: `tests/test_fractional_stamps.py` covers the actual ns samples, seconds/ms/us/ns fractional variants, false epochs, and identical floored metadata times with distinct receipt identities.
7. Generalization: its focused eval requires all nine tests to pass and verifies that the former integer-only rule fails the high-rate receipt regression.
8. Causality: a single receiver UTC nanosecond sample produces the existing floored causal availability millisecond; broker stamps never move receipt availability. The raw source/receiver delta is explicitly an uncorrected difference between clocks.
9. Prospective rollout: preserve the original pilot as failed operational evidence. Freeze the new source version and a new registration in a new namespace before its future start; never rewrite the old source hashes or chronology.
10. Verification: `python3 -m services.otc_collector.tests.test_fractional_stamps` runs only the focused offline regression/eval; no broker or credential reads occur.

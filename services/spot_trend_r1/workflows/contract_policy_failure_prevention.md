# Ten-step contract and exact-arithmetic failure-prevention workflow

Use this workflow when changing a requirements planner, a caller-selected policy file, a synthetic accounting proof, or an optimization/cache. The recorded failures were incomplete semantic validation that printed unsupported policy beside a fixed inventory, finite-context Decimal arithmetic that hid an over-cash debit or erased a base fee, and caller mutation of cached output windows that contaminated a later same-process report. These steps prevent the classes without changing approved strategy rules.

1. **Freeze the reference and measurable outcome.** Record the approved contract, source identities and expected requirement grid before editing code. A policy change needs a reviewed protocol/code version. Do not reinterpret unknown fees, capital, precision, live budgets or authorization as defaults.
2. **Choose arithmetic and ownership explicitly.** Use exact Fraction amounts and independent integer grid floors for deterministic cash/base/cost conservation. An unrestricted coefficient length cannot be justified by a finite Decimal context. Define expected debits and fees independently of the implementation. Cached values must be recursively immutable and private, or recursively copied before caller access. A shallow copy does not isolate nested windows, dictionaries or lists. Every returned mutable container belongs to that call; caller annotation of an earlier report must never change a subsequent plan from identical bytes in the same already-loaded module.
3. **Preserve the original evidence.** Save the original planner, raw contract, SHA256 identities and attack input under a task-specific `/tmp` evidence directory. Keep the supported semantic fingerprint separate from the raw file hash. Do not overwrite the original snapshots after repair.
4. **Prove the regression is red before repairing.** Add `tests/test_contract_policy.py` cases for the reported policy attack, representative nested additions/omissions and numerical/type substitutions. Put exhaustive leaf/container sweeps in the eval lane. Run the regression file against the unchanged planner and save the failure log. Also save a real CLI attack showing its original exit/status/output. The exact-arithmetic regressions must reject a tiny over-cash debit and retain the tiny base fee exactly.
5. **Validate the entire contract before use.** `plan.validate_contract` must accept only the supported typed semantic tree, independent of the selected file. Reject unknown/additional keys at every depth and detect missing fields before field lookup. Do not grade only weights/clocks while printing unchecked retry, transfer, terminal, B0 or authorization rules.
6. **Preserve syntax-equivalent provenance.** Verify that key order, indentation and JSON escape changes are accepted, while arrays and scalar types remain fixed. `test_cli_accepts_policy_equivalent_layout_preserving_raw_provenance` must show identical requirements and semantic hash but the actual raw contract hash. No hash is an R2 lock.
7. **Run the complete local gate.** Set `D3_SERVICE` to the service directory and run the command below from repository root. Measure the full subprocess wall time, including interpreter startup and fixtures, and require less than 2 seconds. `test_cli_attack_exits_two_with_no_stdout_before_source_interpretation` proves policy rejection occurs before a source read. `test_tiny_overspend_is_rejected_without_rounding_to_cash` and `test_tiny_base_fee_is_retained_exactly` protect the arithmetic domain. `test_returned_report_mutation_does_not_change_next_plan` edits requirement maps, windows, blocker lists and nested caller annotations, then compares the next same-module report with the original canonical bytes without reloading or clearing caches.
8. **Run the generated deterministic eval lane.** Run the second command below with a task-specific `D3_EVIDENCE` directory. `evals/policy_mutations.py` must mutate every leaf, test additions/omissions/renames in every object, alter array shapes/order, generate combined attacks and exercise the real CLI. `evaluate_fraction_extremes` tests tiny fees, over-balance debits and both sides of an integer grid floor over seeded coefficient lengths. `evals/output_ownership.py` mutates all purpose lists, nested windows/blocker lists and seeded containers in retained earlier outputs; every later canonical report must be unchanged, with no mutable identity shared with any retained report. The same module stays loaded throughout. Preserve a controlled shared-window/list-cache mutation proving these guards fail when output ownership is broken. The threshold is 100% of critical cases; save summary and per-case evidence.
9. **Submit the deliverable and reference to a cold critic.** The critic receives artifacts and the frozen reference, without builder reasoning. It must rerun the documented commands and attack actual CLI rejection, fee conservation, failed-entry/exit consequences and midnight/final-day boundaries. Preserve its verdict separately; passing local tests is not a critic PASS.
10. **Ship only the reviewed supported result.** Confirm that contract/source bytes, approved weights, signals, retry policy, terminal clocks and requirements coverage remain unchanged unless an approved version explicitly changes them. Check that every linked service document is included and every source file is visible to Git. Validate the complete proposed patch with `delivery.check_patch`, which invokes `git apply --check --whitespace=error-all`, before staging. Include untracked files: `git diff --check` alone missed the eval source's extra EOF blank line. The focused `test_regression_eval_source_passes_before_staging` gate must fail if that original source defect returns; `test_untracked_eof_blank_line_is_rejected` protects the validator. `evals/delivery_checks.py` tests new/existing files, trailing whitespace, valid interior blanks and all service sources. Build any temporary patch baseline from HEAD's tree and modes; index-known additions may not exist in HEAD. Permit only the task's staged subset, preserve the actual index, reject unrelated staged paths, and bind source hashes plus Git file modes in the published manifest/guard. Pass `-c diff.autoRefreshIndex=false` to every helper and guard Git read, alongside `GIT_OPTIONAL_LOCKS=0`; optional locks alone did not stop zero-stat index entries from being rewritten. In disposable shipping fixtures, recreate that refresh with `git update-index --cacheinfo` using the same blob/mode, prove the old reader changes the index, and require the corrected reader, preparer and published guard to preserve index and raw staged/unstaged diff bytes. Exercise temporary-baseline checks with the `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE` exported by commit hooks while keeping unrelated environment and active hooks intact. Run `test_saved_requirements_match_fresh_canonical_output`: internal hashes alone cannot reject an altered snapshot whose hashes were recomputed. The saved artifact must match the current canonical result byte-for-byte. Include code, tests, evals, docs and the evidence paths in the parent-owned commit/hook integration. This offline requirements service needs no process restart. It grants no downloads, fills, returns, live authority or R2 promotion.

```bash
D3_SERVICE=services/spot_trend_r1
D3_EVIDENCE=/tmp/d3-policy-repair
mkdir -p "$D3_EVIDENCE"
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s "$D3_SERVICE/tests" -q \
  > "$D3_EVIDENCE/gate.stdout" 2> "$D3_EVIDENCE/gate.stderr"
PYTHONDONTWRITEBYTECODE=1 python3 "$D3_SERVICE/evals/eval_scenarios.py" \
  --policy-evidence "$D3_EVIDENCE/policy-mutations.json" \
  --ownership-evidence "$D3_EVIDENCE/output-ownership.json" \
  > "$D3_EVIDENCE/eval.json" 2> "$D3_EVIDENCE/eval.stderr"
PYTHONDONTWRITEBYTECODE=1 python3 "$D3_SERVICE/plan.py" \
  --source-dir docs/research/crypto-r1-2026-10-31 \
  > "$D3_EVIDENCE/requirements.json"
```

To reproduce a saved red run without replacing repaired code, load the saved original planner as the test module in an isolated Python process; preserve the original SHA256 and fail count in that process's evidence. Never restore the bug into the working deliverable or weaken its gate threshold to obtain a green result.
